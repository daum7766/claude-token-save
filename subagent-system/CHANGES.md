# 키트 변경 내역

버전마다 바뀐 것. 업데이트할 때 Claude가 설치본 버전보다 새 항목(`## <버전>` 머리줄로 나뉘고 새 항목이 위에 온다)을 사용자에게 보여 준다. 항목을 더하는 법은 키트 관리용 `CLAUDE.md`에 있다.

## 2026.10.26

- 규칙과 체크리스트를 고친 기록이 생겼다(`records/fixes.tsv`, 업데이트가 건드리지 않는다). 고칠 때마다 `subagent-retro.js --fix`로 한 줄 적고, `--fixes`가 고친 뒤 같은 지적이 서로 다른 에이전트 둘이나 서로 다른 세션 둘에서 다시 나오는지(재발), 같은 태그의 모자람이 쌓였는지(쌓임), 고친 뒤 재지시와 모자람 비율이 늘었는지(나빠짐 의심)를 가려 처리할 것을 찍는다. 고친 방식은 문장이나 체크리스트, 스크립트 또는 훅, 바깥 자료 조사 순으로 한 단계씩 올라간다. 나빠짐 의심은 뒤쪽 나쁜 줄이 3건 이상이고 비율이 0.1 이상 늘었을 때만 걸리고, 검토해서 그 고침이 원인이 아니면 `--how 무관`으로 적어 닫는다(`무관`은 쌓임과 재발 판정에는 없는 기록처럼 쓰인다). 처리할 것 줄은 모자람과 정정의 건수와 근거를 나눠 적고, 효과 표는 고침 기록도 처리할 것도 없는 이름표를 뺀다. `--due`와 `--fixes`의 `--project`는 절대 경로여야 한다.
- 사용 기록 메모의 표시가 `모자람(<태그>[,<태그>…]): <요지>`와 `개선(<태그>): <요지>`로 바뀌었다. `--log`가 처음 보는 태그를 알리면서 비슷한 기존 태그를 보여 주고, `--shortfalls`와 `--extract`의 이름표 목록이 새 꼴을 읽는다. 옛 꼴 `모자람: <요지>`도 읽지만 판정에는 들지 않는다.
- 맡긴 작업이 끝날 때 `--due --project <세션을 시작한 폴더>`가 「그 자리에서 고칠 것 N건」을 알리면, 메인이 회고보다 먼저 그 건을 처리한다. 첫 줄의 `ask`, `auto`, `wait` 판정은 그대로다.
- 회고의 바로 적용이 넓어졌다. `autoApplyRules`가 참이면 근거 기록이 있는 지시문 체크리스트 고침과 사용자 규칙 구역, `~/.claude/CLAUDE.md`의 표시 주석 구역 밖 규칙 문장 고침을 묻지 않고 하고, 고치기 전에 체크리스트와 `~/.claude/CLAUDE.md`도 백업한다. 프로젝트 `CLAUDE.md`, 정책 결정, 「무조건 Opus」 목록, 새 파일 만들기는 계속 묻는다.
- `config.json`에 `autoApplyRules`가 생겼다. 처음 설치의 질문이 열 번이 되었고(Q6), 업데이트는 키가 없으면 다른 단계와 상관없이 번호 없는 독립 단계(「규칙 바로 고치기 질문」)에서 한 번 묻고, 검증이 이 키를 확인한다. 키가 없는 설치본은 답하기 전까지 참으로 읽힌다. `/retro`의 상태에서 값이 보인다. 끄려면 `kit-setup.js --config-set <config.json> autoApplyRules false`다.
- 구역 문장(`CLAUDE.md`의 `subagent-system` 구역)이 바뀌었다. 작업이 끝날 때 `--due --project <세션을 시작한 폴더>`를 돌려 「그 자리에서 고칠 것」을 먼저 처리하고, 같은 지적이 되풀이되면 스크립트나 훅을 거쳐 바깥 자료 조사로 올리며, 자동 회고의 묻지 않는 예외에 사용자 규칙 구역, 체크리스트, `~/.claude/CLAUDE.md`의 구역 밖, 고침 기록이 들어갔다. 업데이트 5번이 구역 차이를 보여 주고 묻는다. `/retro` 스킬의 같은 예외 줄도 바뀌었다.
- `SUBAGENT_GUIDE.md`의 「기록과 회고」에 메모 표시, 그 자리에서 고치기, 고침 기록 쓰는 때가 더해졌고 기록이 세 가지에서 네 가지가 되었다. 최종 리뷰 결함을 만든 에이전트의 agentId로 `올림`을 적는 문장이 리뷰 보고의 agentId를 쓰게 바뀌었다.
- `SUBAGENT_BRIEF_CHECKLIST.md`의 「판단과 리뷰를 맡길 때」에 최종 코드 리뷰와 문서 검수 보고에 결함마다 결함을 만든 에이전트의 agentId를 적게 하고, 메인이 리뷰 지시문에 단계와 구현한 agentId의 짝을 적어 주게 하는 줄이 더해졌다. 업데이트의 체크리스트 대조가 이 줄을 권한다.
- 정의 10개에서 범위 밖에서 본 개선거리를 일하는 방식과 규칙의 것과 코드의 것으로 나눠 적게 했다. 일하는 방식과 규칙의 개선거리는 메인이 `개선(<태그>)`로 적는다.

## 2026.10.25

- agent-meter 0.2.1: keep-alive의 연장 요청이 응답은 왔는데 캐시를 읽지 못하면, 또는 응답 없이 끝나는 일(오류, 거절)이 연달아 두 번 되풀이되면 그 세션에서는 연장과 유휴 압축 건너뛰기를 멈추고 한 번만 알린다. 한 번의 일시 오류는 그 회차만 만료 알림으로 대신한다. 멈춤과 거절 표시는 `/clear`나 resume으로 세션이 끝나면 지워진다. 「유휴 압축을 건너뛰었습니다」 알림은 서브에이전트를 한 번 기다리는 동안(메인이 다음 요청을 보낼 때까지) 한 번만 뜬다. keep-alive를 끄면 실행 중인 에이전트 목록도 읽지 않는다.
- agent-meter 0.2.1: 훅 안의 엔진 호출(시계, 타이머, 명령 등록, 상태줄, 화면 부품)이 조직 정책으로 거절돼도 훅이 오류로 끝나지 않는다. 「hook skipped」 경고가 줄고, 거절된 기능만 빠진다. README의 「알아 둘 것」에 경고가 날 때 확인하는 순서가 더해졌다.
- 이미 agent-meter가 깔린 컴퓨터도 keep-alive를 고를 수 있다. 처음 설치와 업데이트가 지금 값을 보이고 켤지 한 번 묻고, 답은 `config.json`의 `agentMeterKeepaliveAsked`로 남겨 다시 묻지 않는다. 바꾼 값은 Claude Code를 다시 열어야 적용된다.
- 설치, 업데이트, 제거의 `node -e` 한 줄 명령이 `scripts/kit-setup.js`의 하위 명령으로 옮겨졌다. 회고의 `모자람:` 모으기와 `removedDefs` 고치기는 `subagent-retro.js`의 `--shortfalls`, `--remove-def`, `--restore-def`로, Fable 판정은 `--check-fable`로 옮겼다. 동작은 같다.
- 구역 고침 줄(`구역:`으로 시작하는 줄)에 「<절이나 항목 이름>에 「<새 문장>」을 더한다」 꼴이 정식으로 생겼다. 업데이트가 「A 대신 B」와 「더한다」 두 꼴을 따로 점검한다.
- extras에 선택 항목 「목표와 방법」(Q4의 e)이 생겼다. 이미 extras를 깐 컴퓨터는 업데이트가 한 번 묻고, 거절하면 `goalMethodDeclined`로 남겨 다시 묻지 않는다. 처음 설치의 질문은 아홉 번이 되었다.

## 2026.10.21

- agent-meter를 키트 폴더의 설치 스크립트가 아니라 플러그인 마켓플레이스로 깐다. 이 저장소(GitHub `daum7766/claude-token-save`)가 마켓플레이스 `claude-token-save`이고 agent-meter가 그 안의 플러그인이다. 설치는 `claude plugin install agent-meter --marketplace daum7766/claude-token-save` 한 줄이고, `install-agent-meter.mjs`와 `install-agent-meter.sh`는 없어졌다. 처음 설치와 업데이트가 이 명령을 대신 돌린다.
- 옛 설치 스크립트로 agent-meter를 깐 컴퓨터는 업데이트가 마켓플레이스 설치로 옮긴다. 묻지 않고 하며, 새 플러그인이 `✔ enabled`로 확인된 뒤에만 옛것을 치운다. 치우는 것은 `settings.json`의 `env.CLAUDE_CODE_PLUGIN_DIRS`에서 agent-meter 폴더 항목(다른 항목은 그대로)과 `env.AGENT_METER_KEEPALIVE` 키이고, 고치기 전 `settings.json`이 `.bak-agent-meter-<날짜-시각>`으로 남는다. `~/.claude/mods/agent-meter` 폴더는 지우지 않고 `~/.claude/agent-meter-backup-<날짜-시각>/`으로 옮긴다. 옛 항목이 남으면 옛 폴더가 마켓플레이스 복사본을 대신해 새 버전이 읽히지 않아서다. 업데이트가 끝나면 Claude Code를 다시 열어야 새 방식으로 읽힌다.
- keep-alive 설정이 `env.AGENT_METER_KEEPALIVE`에서 플러그인 설정 `keep_alive`(기본 켬)로 바뀌었다. 옛 값이 끔이었으면 업데이트가 새 설정으로 옮긴다. 이제 Claude Code 안에서 `/config`의 agent-meter 줄(또는 `/plugin configure agent-meter@claude-token-save`)로 바꾸고, 바꾼 뒤에는 Claude Code를 다시 연다.
- 사용자가 추가한 마켓플레이스는 자동 업데이트가 꺼져 있다. agent-meter 새 버전은 이 키트를 업데이트할 때 함께 올라가고, 키트 업데이트 없이 올리려면 `claude plugin marketplace update claude-token-save`와 `claude plugin update agent-meter@claude-token-save`를 돌린다.
- 조직 설정 검사가 바뀌었다. 예전에는 `disableSideloadFlags`가 켜진 컴퓨터에 agent-meter를 깔지 않았지만, 이제는 마켓플레이스 출처를 제한하는 `strictKnownMarketplaces`(허용 목록)와 `blockedMarketplaces`(차단 목록)가 이 저장소를 막는지를 본다. 마켓플레이스로 깐 agent-meter는 `CLAUDE_CODE_PLUGIN_DIRS`를 쓰지 않으므로 `disableSideloadFlags`가 켜져 있어도 깔린다. 그래서 `CLAUDE_CODE_PLUGIN_DIRS` 시작 오류 때문에 agent-meter를 지우는 안내도 없어졌다.
- 제거도 바뀌었다. 마켓플레이스로 깐 agent-meter는 `claude plugin uninstall`로 지우고(저장된 옵션도 함께 지워진다) 마켓플레이스 등록도 뺄지 묻는다. 옛 설치 스크립트로 깐 흔적은 이전처럼 `env`와 mod 폴더에서 치운다.

## 2026.10.20

- 회고의 「속도와 비용 보기」를 바꿨다. 평균 시간이 긴 칸 셋의 시간을 나눠 보이던 것을, 지난 회고 뒤 합계 시간이 가장 큰 칸이나 절차 1건의 작업 기록을 서브에이전트(리뷰어)가 읽어 낭비를 찾고 바꿀 자리와 줄어들 시간을 붙인 개선안을 내는 흐름으로 바꿨다. 대상 고르기와 자료 만들기는 새 `speed-review.js --pick --out`이 하고, 리뷰어는 파일을 쓰지 않고 제안을 답으로 돌려준다. 묻기 방식은 메인이 사용자에게 묻고, 자동 회고는 메인이 회고 서브에이전트를 띄우기 전에 `--pick`을 돌려 리뷰어를 함께 띄우고 답을 `retro-pending.md`에 덧붙인다. 리뷰어가 읽는 기준은 `RETRO.md`의 「낭비의 꼴」 아홉 가지다.
