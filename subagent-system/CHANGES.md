# 키트 변경 내역

버전마다 바뀐 것. 업데이트할 때 Claude가 설치본 버전보다 새 항목(`## <버전>` 머리줄로 나뉘고 새 항목이 위에 온다)을 사용자에게 보여 준다. 항목을 더하는 법은 키트 관리용 `CLAUDE.md`에 있다.

## 2026.10.30.4

승인 창을 기록해 줄이고, 개인용과 회사용을 가르는 기준을 profile 하나로 통일했다. 맡길 때 읽는 문서가 줄었다.

- 끊긴 처음 설치를 다른 선택으로 다시 `install`하면, 앞 설치가 놓았는데 이번에 고르지 않은 규칙, 스킬, 훅을 키트가 놓은 그대로일 때 지우고(`unchosenRemoved`) 고친 것은 두고 알린다(`unchosenKept`). 지금까지는 그대로 남아 「안 깔림」 보고와 달리 세션마다 읽혔다.
- 필요한 Node가 24 이상으로 바뀌었다. 키트를 시험하는 판이 24이고, 18 초기판에서는 설치 확인 시험이 실패했다. 낮은 판을 쓰면 Node를 올린 뒤 업데이트한다.
- commit-msg 훅을 저장소에 걸기 전에 이미 걸린 `core.hooksPath`(husky 등)와 `.git/hooks`를 보고, 있으면 그 훅이 꺼진다는 것을 보이고 묻는다. 회고 쓰기 허용은 `MIGRATED_USER_RULES.md`도 정책 문서처럼 확인 창으로 넘긴다.
- CLAUDE.md 정리를 물을지 가르는 판정이 설치, 업데이트, 회고에서 하나로 통일됐다. 지금까지는 설치와 업데이트가 늘 읽히는 줄(`CLAUDE.md`, `@`로 불러온 파일, `paths` 없는 `rules/`)의 합으로 세는데 회고는 `CLAUDE.md` 한 파일만 세어, 같은 상태에서 한쪽은 정리를 권하고 한쪽은 기준 이하라고 했다. 이제 셋 모두 합으로 세고, 기준은 `config.json`의 `claudeMdLimitLines`(없으면 80줄)를 읽으며(`claudeMdTidy.js`도 `--limit`이 없으면 이 키를 읽는다), 사용자가 정리를 마다해 `claudeMdKeptLines`에 남긴 줄 수에서 20줄 이내이면 업데이트도 같은 정리를 되묻지 않는다. 업데이트 결과 `claudeMd`에 `tidyTarget`, `tidyReason`, `keptLines`가 더해졌다. 회고의 「CLAUDE.md 정리」 줄은 「늘 읽히는 줄 합 N줄(CLAUDE.md N줄, 키트 구역 N줄)」로 바뀌었다.
- 개인용으로 바꾸는 `set-profile`이 `update` 없이도 출력의 `settings.gitAsk.keptCommitAsks`로 전역에 남은 commit, merge, rebase, push 확인 목록을 보인다(`settings.json`은 쓰지 않는다). 지금까지는 `update --dry-run`을 따로 돌려야 목록이 나와, 비었다고 읽고 넘어가면 프로젝트별 허용이 전역 확인을 이기지 못한 채 남았다.
- 회고 쓰기 허용 훅이 정의와 스킬 머리를 BOM이나 앞 공백이 있어도 읽고, `---`로 시작하는데 닫는 `---`가 없어 머리를 읽지 못하는 파일은 열지 않는다. 지금까지는 머리를 못 읽으면 키가 없다고 보고 열었다. `---`로 시작하지 않는 문서는 그대로 열린다.
- 회고 판정 명령은 서브에이전트를 띄웠거나 도구 호출이 열 번 넘은 작업의 최종 보고 뒤에만 돌린다. 작은 요청마다 돌리던 비용이 빠진다.
- `uninstall` 결과가 commit-msg 훅을 건 저장소의 `core.hooksPath`를 풀라고 알리고, 제거 절차가 풀지 묻는다.
- 회고 쓰기 허용 훅이 막을 자리를 나열하던 방식에서 열 자리를 나열하는 방식으로 바뀌었다. 확인 창 없이 쓰는 자리는 문서, 요율표, 규칙(`rules/`), 정의와 스킬의 `.md`뿐이고 스크립트, 훅, 훅 등록 원본은 열지 않는다. 정의와 스킬은 머리 키가 `name`, `description`, `model`, `effort`, `argument-hint`, `disable-model-invocation`일 때만 열린다. 머리는 0열 `이름: 값` 줄로만 되어 있어야 하고, 들여쓴 맵이나 `?` 키처럼 YAML이 키로 읽는 다른 꼴이 있으면 확인 창이 뜬다.
- 회사용은 agent-meter를 깔 때 캐시 연장(keep-alive)을 끈다. 회사 관리 설정이 mod의 요청을 막아 「hook skipped」 경고가 되풀이되기 때문이다. 업데이트 때 켜져 있으면 끄고 알린다. 표와 기록은 그대로다.
- 승인 창 기록 훅(`hooks/ask-log.js`)이 개인용과 회사용 모두 늘 설치된다. Claude Code가 사용자에게 승인 창을 띄울 때마다 설정 폴더의 `permission-asks.jsonl`에 한 줄을 남기고, 출력이 없어 승인 결정에는 끼어들지 않는다. 회고 쓰기 허용 훅이 `settings.json`에 걸려 있어 창이 뜨지 않는 요청은 적지 않고, 쓰기 허용을 켰어도 훅이 걸리기 전이면 창이 뜨므로 적는다. 업데이트가 PermissionRequest 훅 한 줄을 `settings.json`에 더한다.
- 회고가 이 기록으로 「승인 창 보기」를 해 창을 정말 물을 것, 검사 훅의 오탐, 명령 모양 탓, 풀어도 될 후보로 나눠 셋째까지 고치고 넷째만 `문지기 풀기`로 사용자에게 올린다.
- 맡길 때마다 읽는 `docs/SUBAGENT_GUIDE.md`에서 가끔 쓰는 절이 새 문서 `docs/SUBAGENT_SITUATIONS.md`로 떨어졌다(내려 보기 시험, 마지막 올리기, 그 자리에서 고치기, 구현 계획 표기, 검토를 끊는 때, 제안 목록 등). GUIDE 맨 아래가 상황별로 어느 절을 읽을지 가리킨다. 업데이트가 새 문서를 깔고 병합한다.
- 설치 질문 방식이 바뀌었다. Q4(권장 규칙)와 Q5(권장 스킬과 훅)는 항목을 번호로 한 메시지에 모두 보이고 「추천대로」나 번호 목록으로 한 번에 고른다. 「우선순위」 칸은 설치 때 묻지 않고 질과 비용이 처음 부딪힐 때 채운다.
- `rules/kit-core.md`에 두 줄이 늘었다. 일 한 묶음을 끝냈다고 보고하기 전에 목표와 끝난 기준에 비춰 빠진 것을 따져 AI 몫이면 하고 사용자 몫이면 정할 것으로 올리는 줄, 애매할 때의 문턱이 사용 방식(개인용, 회사용)을 따른다는 줄이다. 늘 읽히는 줄이 둘 늘었다.
- 개인용과 회사용 판정이 `profile` 하나로 통일됐다. 물을 것 세기, 바로 고치기와 만들기, 고친 근거를 남기는 곳, 애매할 때의 문턱을 따로 바꾸던 설정 키 넷(`autoApplyRules`, `autoCreate`, `actThreshold`, `methodCommit`)이 없어졌다. 개인용은 표 칸 조정과 쪼개기, 정의 description 맞추기, 규칙과 체크리스트 고침, 스킬, 훅, 스크립트, 정의 만들기와 지우기, 바깥 자료 조사를 바로 하고 근거를 커밋 메시지에 남기며 애매하면 하고 알린다. 회사용은 이 일을 모두 제안으로 모아 승인받은 뒤 하고 근거를 최종 보고의 「하고 알린 것」에 쓰며 되돌리는 비용이 거의 없는 것만 한다.
  - 옛 설치의 `config.json`에 이 키가 있으면 값을 읽지 않는다. `update`와 `set-profile`이 키를 지우고 `notes`로 알리며, `--config-set`은 이 키를 거절한다. 예전에 키를 따로 바꿔 두었다면 그 값은 사라지고 `profile`을 따른다. 다른 쪽 동작을 바라면 `set-profile`로 profile을 바꾼다.
  - 따로 바꾸는 키는 `retroMode`(회고를 언제 누가 돌리나), `retroWriteAllow`(권한 스위치), `commitCheck`뿐이다. `--status`는 「바로 고치기」와 「애매할 때」 줄에 profile이 정한 값을 찍는다.
  - 개인용에서 `/retro ask`는 받지 않고 `set-profile company`를 알린다. `/retro auto`는 실패로 묻기가 된 개인용을 다시 켜는 길로도 쓴다.
  - 판정의 원본이 새 스크립트 `scripts/kitProfile.js`다. 업데이트가 깐다.
- 회고는 `retroMode`가 `ask`여도 회고 서브에이전트가 한다. 지금까지는 사용자가 하자고 하면 메인이 「회고 단계」를 직접 해 이 문서 전체와 각 출력이 메인 문맥에 쌓이고 메인이 멈췄으며, 고치기 전 백업도 서브에이전트 길에만 있었다. 이제 `ask`에서 하자고 하거나 `/retro now`를 치면 메인이 `--claim`부터 `auto`와 같은 길로 서브에이전트를 띄우고, 지시에 `profile`(회사용은 제안으로 모음)을 넣는다. 문서 내용 검토도 서브에이전트가 직접 읽는다.
- 업데이트가 스크립트와 훅을 줄 병합하지 않고 키트 것으로 바꾼다는 예외를 업데이트 절차에 적었다. 사용자가 고친 스크립트나 훅이 덮이면 옆 `.bak-update-…`에 백업이 남고 `notes`가 파일 이름을 알리며, 절차가 차이를 보고 다시 넣을지 정하게 한다. 회고가 키트 스크립트를 고치면 `kitSourcePath`가 없을 때 다음 업데이트가 덮으므로 키트 원본에 올리거나 제안 목록에 두게 했다.
- 2026.10.30.3보다 앞선 설치본은 `config.json`에 `profile`이 없다. 이런 설치본의 첫 `update`는 아무것도 바꾸지 않고 멈추며(`needsProfile`, 종료 코드 2), 업데이트 절차가 사용자에게 개인용인지 회사용인지 한 번 묻고 `set-profile`을 돌린 뒤 `update`를 다시 돌린다. 이번 판의 회고 스크립트는 `profile`이 없는 설정을 회사용(묻기)으로 본다.
- 원칙은 「명령은 보호를 느슨하게 바꾸지 않는다」이다. 권한과 보호 스위치(`retroWriteAllow`, `commitCheck`와 이 둘이 거는 훅)는 키트의 어떤 명령(`install`, `update`, `set-profile`, `--config-unset`)도 느슨한 쪽으로 바꾸지 않고, 푸는 것은 사용자가 답한 뒤 `--config-set`으로만 한다. 조이는 쪽은 명령이 하고 `notes`로 알린다.
  - `set-profile`이 바꾸는 것은 `profile`, `retroMode`, 회사용으로 갈 때의 `retroWriteAllow`다. 회사용으로 바꾸면 켜져 있던 `retroWriteAllow`가 꺼지고 `settings.json`의 `retro-write-allow` 훅 등록도 빠진다(결과의 `writeAllowHook`에 백업 경로). 개인용으로 갈 때와 `commitCheck`는 새 profile의 기본값과 달라도 두고 `notes`에 「바꾸려면 묻고 --config-set」을 알린다. 지금까지는 개인용에서 회사용으로 바꾸면 `commitCheck`가 막기에서 끔으로 풀렸고, 회사용에서 개인용으로 바꾸면 `retroWriteAllow`가 켜졌다.
  - 설치가 끊겨 VERSION이 없는 채로 다른 profile을 골라 `install`을 다시 돌리면 같은 규칙으로 옮긴다. 지금까지는 개인용으로 깔다 끊긴 설치를 회사용으로 다시 돌리면 쓰기 허용과 자동 회고가 소리 없이 남았다.
  - `--config-set`으로 `retroWriteAllow`를 켜거나 끄면 `settings.json`의 `retro-write-allow` 훅 등록도 같은 자리에서 맞춘다(`--config-unset`은 등록을 뺀다). 지금까지는 켠 뒤 `update`를 한 번 더 돌려야 걸렸다. 키트 폴더가 아닌 곳의 스크립트로 켜면 훅을 못 걸고 `update`를 알린다.
  - 키가 없으면 안전한 쪽으로 본다: `retroMode`는 묻기, `retroWriteAllow`는 허용 안 함, `commitCheck`는 검사. `update`가 빠진 `retroWriteAllow`는 false로, 빠진 `commitCheck`는 `commit-msg` 훅이 깔려 있으면 `block`으로 채운다. 업데이트 절차 6단계가 켤지 묻는 것은 그대로다.
  - 시험이 (처음 profile, `commit-msg` 설치 여부, `set-profile` 대상, 지운 키)의 모든 조합과 (처음 profile, 다시 고른 profile)의 네 조합에서 쓰기 허용 훅 판정과 등록, 커밋이 막히는지, `--status` 줄을 이 원칙과 대조한다.
- 회사용이 `commit-msg` 훅을 고르면 설치 절차가 `commitCheck`를 `block`으로 바꾸게 한다. 지금까지는 훅을 놓아도 `commitCheck`가 `off`라 아무것도 막지 않았다.
- 개인용인데 전역 `permissions.ask`에 commit, merge, rebase, push 확인이 남아 있으면 `update`와 `set-profile` 뒤 그 목록을 보이고 뺄지 묻는다. 키트 스크립트는 이 항목을 줄이지 않는다. 개인용 git 확인 목록에서는 그 넷이 빠졌다.
- 개인용 자동 회고가 `~/.claude`를 고치면 메인이 고친 파일만 커밋한다. 키트 작업 트리를 함께 고치면 `VERSION`과 `CHANGES.md`가 고친 파일 목록에 든다. `~/.claude`가 git 저장소가 아니거나 회사용이면 근거를 최종 보고의 「하고 알린 것」에 쓴다.
- 회고가 바로 적용한 탐색 결과도 제안 목록에 `- 출처: 탐색 <날짜>`와 `- 결과: 채택` 한 줄로 남기고, 회고 백업이 회고가 고치는 파일(이 문서와 `rates.json` 포함)을 다 담는다.
- 지시문 검사 훅이 표 칸 이름의 시험, 최저, 고정 표시를 회고 스크립트와 같은 꼴로 읽어, 표보다 높여 보내는 지시의 높임 검사에서 쪼갠 두 칸이 한 이름으로 합쳐지지 않는다.
- 내려 보기 시험은 구간마다 2건 이상 쌓일 때까지 비용을 판정하지 않고 「모으는 중」으로 둔다. `--status`가 애매할 때의 문턱(profile이 정한 값)과 시험 구간 안 보낸 건수를 찍는다.
- 문서 점검(`docs/DOC_WRITING.md`)에 다섯째 관점 「효율」이 늘었다. 문서대로 일하면 토큰, 시간, 사용자 질문이 목표에 비해 많이 드는지 보고 지적은 「비용」 칸으로 따로 낸다. `kit-docs.md`가 다섯 관점이라고 말한다.
- 정의 열 개의 git 금지 줄에 `git worktree`가 들었다. `subagent-usage.js`는 `--help`를 받고 모르는 인자는 사용법과 함께 거절한다. 직군별 체크리스트 줄은 공통 줄에 없는 것만 두고 설치 때 뜻을 견주지 않는다.
- 실패해 올려 다시 보내는 지시(마지막 Fable 단계 포함)는 지시문에 `올림: <앞 정의와 실패 까닭>` 줄을 넣는다. 지시문 검사 훅이 이 줄이 있으면 표 칸보다 높은 정의여도 `높임:`을 요구하지 않고, 막을 때 내는 문구에도 이 길이 들었다. 처음 보냄의 높임과 올림이 기록에서 섞이지 않는다.
