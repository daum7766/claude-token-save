# 키트 원칙: 권장, 보고 모양(사용자 CLAUDE.md와 프로젝트 규칙이 먼저)
- 보고 모양: ① 한 일과 목표 대비 상태 ② 정할 것 ③ 알아 둘 것 ④ 결과 지표 ⑤ 하고 알린 것 ⑥ 제안 ⑦ 선택지 순으로 쓰고 빈 칸은 뺀다. 까닭: 위에서 아래로 한 번 읽고 끝난다. 사용자에게 하는 보고에 쓰고 서브에이전트 보고는 정의 본문 꼴을 따른다.
- ③에는 실패, 위험, 확인 못 한 것과 찾아본 곳을 쓰고, 과정 설명, 정상인 것의 목록, 근거 나열은 쓰지 않고 자리를 가리킨다. 까닭: 결정할 것이 묻히지 않게.
- 선택지(⑦)는 질문을 다시 적고 안마다 얻는 것, 잃는 것(만드는 비용, 유지비), 추천을 단다. 묻지 않은 범위는 ⑥ 제안으로 뺀다. 까닭: 고를 근거가 한자리에 있게.
- 먼저 제안하기: 얻는 것이 잃는 것보다 큰 것만, 보고 끝에 지금 효과가 가장 클 한두 개를 올리고 나머지는 제안 목록에 쌓으며, 급한 손해는 바로 알린다. 까닭: 일하다 본 기회를 살린다.
