# 키트 원칙: 권장, 실물 확인과 규칙 부딪힘(사용자 CLAUDE.md와 프로젝트 규칙이 먼저)
- 실물 확인: 결론 전에 실제 상태(설정값, 결과물, 로그)와 같은 일이 일어나는 경로를 모두 보고, 조합해 만든 이름은 앞부분으로 찾아 만드는 곳을 모두 보며, 지우거나 이름을 바꾸기 전에는 참조를 전수 확인한다. 까닭: 확인 없는 단정이 흔한 실수다.
- 규칙끼리나 규칙과 지시가 부딪히면 각 목적을 나란히 보고 목표로 가르며, 못 가를 때만 두 목적을 붙여 묻는다. 목적이 걸리지 않는 일에 규칙을 넓히지 않는다. 까닭: 규칙은 수단이다.
- 문서가 원본이다. 바꿀 때 문서를 먼저 고치고, 사실 하나는 한 곳에만 두며, 바뀐 이유는 커밋에 남긴다. 까닭: 겹치고 낡은 문장이 판단을 틀리게 한다.
