# 키트 원칙: 맡기기와 회고

서브에이전트 체계가 기록하고 회고해 스스로 나아지게 하는 원칙이다. 사용자 CLAUDE.md와 프로젝트 규칙이 먼저이고, GUIDE(`SUBAGENT_GUIDE.md`), AUTO_RETRO, RETRO는 `~/.claude/subagent-system/docs/`의 문서다.

- 직접 할지 맡길지는 비용으로 가른다. 지시 쓰는 비용과 확인 비용의 합이 맡겨서 아끼는 비용보다 크면 메인이 한다. 까닭: 맡기는 데도 비용이 든다.
- 맡길 때는 지시문에 `목표:` 줄, 결정 문서 경로, 끝난 기준을 넣고 GUIDE의 지시문 체크리스트와 대조한다(회사 규칙 묶음이 없으면 훅이 이 검사를 하지 않으니 직접 대 본다). 까닭: 전달이 모자라면 재지시 비용이 난다.
- 실무자 결과는 근거(파일과 줄, 명령 출력)를 확인한 뒤 받고, 만든 쪽이 자기 결과를 검수하지 않는다. 까닭: 틀린 결론이 그대로 퍼지지 않게.
- 실무자 보고와 메인 보고의 첫 줄은 목표 대비 결과(이룸, 일부, 못 이룸)와 근거다. 까닭: 회고가 이 줄로 결과를 잰다.
- 서브에이전트가 끝날 때마다 사용 기록을 남긴다(GUIDE 「기록과 회고」). 까닭: 모델 표와 비용 개선의 원자료다.
- 서브에이전트를 띄우거나 도구 호출이 열 번 넘을 것으로 어림되는 일은 시작 전에 토큰과 시간을 어림해 재고(GUIDE 「기록과 회고」의 예산), 크게 넘으면 원인을 알리고 이어 하며, 끝나면 크게 넘거나 덜 든 원인을 기록한다. 그보다 작은 일은 재지 않는다. 까닭: 다음 어림을 맞추되, 짧은 요청마다 재는 도구 호출 셋이 드는 것을 막는다.
- 일하는 방식(스킬, 정의, 체크리스트, 스크립트, 훅)은 AI가 고치고, 사용자 승인이 필요한지는 설치 때 고른 사용 방식(개인용, 회사용)을 따른다. 고치기 전에 근본 원인, 놓친 경우, 더 나은 방법, 부작용을 따진다(`FEEDBACK.md`가 깔려 있으면 그 「바꾸기 전 점검」). 까닭: 쓸수록 체계가 나아진다.
- 일하는 방식은 전후를 재서 품질 유지 이상, 비용 유지 이하, 속도 유지 이상일 때만 바꾼다. 허용선은 AI가 시험하며 고친다. 까닭: 짐작한 개선이 질을 깎지 않게.
- 서브에이전트를 띄웠거나 도구 호출이 열 번 넘은 작업의 최종 보고를 마치면 회고 판정 명령을 돌려 그대로 한다(명령과 절차는 `AUTO_RETRO.md`, 작은 요청마다 돌리면 비용만 든다). 까닭: 회고가 쌓인 기록으로 체계를 고친다.
