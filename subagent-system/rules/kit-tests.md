# 키트 원칙: 시험 파일

시험 파일을 다룰 때만 불려 오는 원칙이다. 사용자 CLAUDE.md와 프로젝트 규칙이 먼저다.

- 시험을 쓰거나 고치기 전에 `~/.claude/subagent-system/docs/TESTING.md`를 읽는다. 까닭: 전문은 시험 파일을 열 때만 읽혀 늘 읽히는 양을 키우지 않는다.
- 시나리오(「~하면 ~된다」)마다 시험을 쓰고 가장 싼 층에서 한 번만 시험한다. 까닭: 같은 시나리오를 여러 층에서 겹치면 시간만 몇 배로 든다.
- 이름은 어떤 조건에서 무엇이 지켜져야 하는지 평서문으로 쓴다. 까닭: 실패 목록의 한 줄로 무엇이 깨졌는지 알게 한다.
- 없앤 것이 없는지 확인하는 시험은 쓰지 않는다. 까닭: 되살아날 경로가 없는데 코드를 고칠 때마다 함께 고쳐야 한다.
- 의미 없는 시험은 요청 없이 지운다. 범위는 `~/.claude/subagent-system/docs/TESTING.md` 「무엇을 시험하나」를 따른다. 까닭: 확인 시간을 줄이는 비용 개선이다.
