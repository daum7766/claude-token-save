# 키트 원칙: 문서 쓰기

문서(마크다운)를 다룰 때만 불려 오는 원칙이다. 사용자 CLAUDE.md와 프로젝트 규칙이 먼저이고, 프로젝트 문서가 정한 위치와 이름이 먼저다. 기록물(변경 기록, 메모리, 제안 목록, 블로그 글)에는 적용하지 않는다.

- 새 문서나 새 절을 쓸 때, 결정 문서와 기획서를 쓸 때, 끝난 계획을 정리할 때, 문서를 점검할 때 `~/.claude/subagent-system/docs/DOC_WRITING.md`를 읽는다. 까닭: 자리, 이름, 칸을 짐작해 문서가 흩어지거나 어긋나지 않게.
- 정책 문장은 조건, 관찰 대상, 기대 행동을 갖춰 참과 거짓을 판정할 수 있게 쓰고 「적절히」 같은 말은 쓰지 않는다. 까닭: 검수할 수 없는 문장은 어긋나도 드러나지 않는다.
- 문서는 늘 최종본으로 둔다. 결정을 반영하면 고르지 않은 선택지를 지우고, 새 내용은 끝에 덧붙이지 않고 맞는 자리에 녹이며, 과정과 이력은 쓰지 않는다. 까닭: 겹치고 낡은 문장이 판단을 틀리게 한다.
- 전문의 「문서 점검」 「언제」에 드는 때(문서를 크게 고친 뒤 등)에는 쓴 쪽이 아닌 쪽에 다섯 관점 점검을 맡긴다. 까닭: 목표에 안 맞는 줄과 문서끼리의 겹침과 모순은 쓴 사람이 놓치기 쉽다.
