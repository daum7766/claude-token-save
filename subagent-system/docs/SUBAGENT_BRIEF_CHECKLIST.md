# 서브에이전트 지시문 체크리스트

서브에이전트에 일을 보내기 전에 한 줄씩 대조하는 목록이다. 모델 배정, git 금지, 보고 형식은 `~/.claude/subagent-system/docs/SUBAGENT_GUIDE.md`와 `~/.claude/agents/` 정의 본문에 있으니 여기 되풀이하지 않는다.

**고치는 법**: 결과가 모자라고 원인이 지시문이면(서브에이전트 보고 끝 「지시에서 모자랐던 점」 참고) 아래 표를 고친다. 「지킬 것」은 지시문에 적을 내용, 「이유」는 빠지면 무엇이 잘못되는지 한 줄이다. 겹치는 줄이 있으면 새 줄을 더하지 않고 그 줄을 고쳐 쓰고, 쓸모가 없어진 줄은 지운다.

## 동시 작업과 파일

| 지킬 것 | 이유 |
|:---|:---|
| 여러 서브에이전트가 같은 시각에 일하면 그 사실을 적는다. 같은 파일은 고치기 직전에 다시 읽고 자기 절만 고치게 하고, 남이 고치는 폴더는 읽기만 하게 하고 작업 폴더를 따로 정해 준다 | 서로의 절이나 같은 원본을 덮어쓴다 |
| 확인 명령(grep처럼 파일에서 글자를 찾는 명령)이 맡긴 범위 밖 파일에 걸릴 수 있으면 고칠지 보고만 할지 정해 준다. 기능이나 내용을 지우거나 옮긴 뒤의 문서 검수는 저장소나 문서 폴더 전체를 찾고, 고친 문서는 문서 전체를 코드나 원자료와 대조하게 한다 | 범위 밖이라 멈춰 묻거나, 지정 문서 밖과 바뀐 절 밖에 옛 문장이 남는다 |
| 검토를 한 번 거친 코드나 문서를 다시 고치게 할 때는 고치기 전 사본이나 diff(바뀐 부분 목록)를 scratchpad(세션의 작업용 임시 폴더)에 남기게 한다 | 고친 부분만 다시 검토할 기준이 없어 범위를 추정한다 |
| 일하는 중인 서브에이전트에 고칠 것은 한 메시지에 모아 한 번만 보낸다 | 잇단 정정을 앞 내용의 취소로 읽고 되돌린다 |
| 한 항목에 기준을 둘 이상 줄 때(빠르기와 정확성, 성능 목표와 하위 호환처럼) 부딪히면 어느 쪽이 먼저인지 적는다 | 우선순위를 추측한다 |

## 이슈 분석과 측정

| 지킬 것 | 이유 |
|:---|:---|
| 지시에 적은 사실(남은 할 일, 기대 결과, 다시 쓸 자료)은 쓴 시점 기준의 참고라고 적는다. 지금 상태와 어긋나면 결정 문서나 원자료로 판정하고 어긋남을 따로 보고하게 한다 | 낡은 지시로 판정이 멈추거나 낡은 사실에 맞춰 일한다 |
