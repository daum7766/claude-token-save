# 서브에이전트 지시문 체크리스트

목표: 서브에이전트가 지시문만 읽고 같은 모자람과 되돌림 없이 한 번에 맞는 결과를 내게 하는 것이다.
서브에이전트에 일을 보내기 전에 한 줄씩 대조하는 목록이다. 모델 배정, git 금지, 보고 형식은 `SUBAGENT_GUIDE.md`와 `~/.claude/agents/` 정의에 있으니 되풀이하지 않는다.

**고치는 법**: 결과가 모자라고 원인이 지시문이면 아래 표를 고친다. 겹치는 줄은 새 줄을 더하지 않고 고쳐 쓰고, 쓸모없어진 줄은 지운다. 줄이 특정 상황을 전제하면 그 전제를 줄에 적는다. 「이유」는 빠지면 무엇이 잘못되는지 한 구절이다.

## 동시 작업과 파일

| 지킬 것 | 이유 |
|:---|:---|
| 여러 서브에이전트가 같은 시각에 일하면 그 사실을 적고, 같은 파일은 고치기 직전에 다시 읽고 자기 절만 고치게 한다 | 서로의 절을 덮어쓴다 |
| 남이 고치는 폴더는 읽기만 하게 하고 작업 폴더를 따로 정해 준다 | 같은 원본을 덮어쓴다 |
| 나눠 맡긴 일이 함께 쓰는 시험, 자료, 장치는 고칠 담당 하나와 이름을 정해 알리고, 같은 시험 파일이나 외부 호출을 동시에 쓰면 순서를 정한다 | 같은 것을 두 번 만들거나 서로 고치다 엇갈린다 |
| 확인 명령(grep 같은 검색)이 맡긴 범위 밖 파일에 걸릴 수 있으면 고칠지 보고만 할지 정해 준다 | 범위 밖이라 멈춰 묻는다 |
| 내용을 지우거나 옮긴 뒤의 문서 검수는 저장소 전체를 찾고, 고친 문서는 전체를 코드나 원자료와 대조하게 한다 | 바뀐 절 밖에 옛 문장이 남는다 |
| 고칠 파일(딸린 시험, 문서, 생성물, 사본까지), 새 문장을 넣을 자리, 경계 사례, 써도 되는 명령, 조건, 목표 대조 기준을 처음 지시에 모두 적고, 정하지 않은 것은 짐작하지 말고 보고하게 한다 | 범위를 짐작하거나 넣을 자리를 몰라 멈춘다 |
| 검토를 거친 코드나 문서를 다시 고치게 할 때는 고치기 전 사본이나 diff를 scratchpad에 남기게 하고 만드는 법(명령, 경로)을 준다 | 고친 부분만 다시 검토할 기준이 없다 |
| git이 추적하지 않는 파일은 `git diff`에 안 나오니 변경 확인을 고치기 전 사본과의 비교로 하게 한다 | 고쳤는지 알 수 없다 |
| 결과물을 복사해 옮기는 일은 원본과 같은지 `diff`로 기계 비교하게 한다 | 눈으로는 달라진 곳을 놓친다 |
| 일하는 중인 서브에이전트에 고칠 것은 한 메시지에 모아 한 번만 보낸다. 같은 파일에 새 일을 얹는 것은 그 에이전트가 측정과 캡처 단계에 들어가기 전에만 하고, 들어간 뒤면 끝난 다음 새로 보낸다 | 잇단 정정을 앞 내용의 취소로 읽고 되돌리며, 측정과 캡처가 끝난 뒤 얹은 일이 이미 한 측정과 캡처를 무효로 만든다 |
| 한 항목에 기준을 둘 이상 줄 때(빠르기와 정확성처럼) 부딪히면 어느 쪽이 먼저인지 적고, 안을 고르게 하면 고르는 기준도 적고, 함께 요구한 조건이 동시에 이뤄질 수 있는지 먼저 확인한다 | 우선순위를 추측하고, 동시에 안 되는 조건을 받아 멈춘다 |
| 지시, 규칙, 문서가 같은 일을 달리 말해 겹칠 수 있으면 어느 쪽을 따를지 적는다 | 따를 쪽을 추측한다 |
| 수치(줄 수, 시간, 크기)를 줄 때는 단위, 세는 대상, 경계 포함 여부를 적는다 | 한도 값이 들어가는지 몰라 추측한다 |
| 「X는 고치지 않는다」 금지를 줄 때는 다른 지시가 X를 건드려야 하지 않는지 보고, 걸리면 허용할 몫을 적는다 | 금지와 부딪힌 일이 남는다 |
| 글자나 값을 가르는 판정 규칙을 줄 때는 바꿀 것과 남길 것의 실제 입력 예시를 둘 이상씩 붙인다 | 판정 경계를 추측해 엉뚱한 문구까지 바꾼다 |
| 같은 판정 일을 여러 실무자에게 묶음으로 나눌 때는 견본 묶음을 먼저 채워 기준을 공통 지시에 적고, 겹칠 때 남길 쪽, 코드 값을 옮긴 표, 손으로 적은 개수, 기준끼리 부딪힐 때의 순서를 미리 정하며, 앞 묶음 보고의 「스스로 정한 기준」을 받는 대로 공통 지시에 보태 뒤 묶음에 넘긴다 | 묶음마다 기준을 추측해 판정이 갈리고 같은 모자람이 묶음 수만큼 쌓인다 |
| 지시문에 든 예시와 옮길 사실은 보내기 전에 결정 문서와 최신 정책 문서에 대 보고, 걷기로 했지만 코드가 아직 있는 기능처럼 시점이 따로 정해진 것을 함께 적는다 | 폐기된 정책을 예로 들어 실무자가 확인에 시간을 쓰거나, 아직 걷을 때가 아닌 것을 지웠다 되돌린다 |
| 생성 단계가 있는 작업은 어느 원본을 고쳐야 남는지, 생성물을 누가 언제 다시 만드는지 적는다 | 고친 파일이 다음 생성 때 덮어써진다 |
| 구조나 배치를 바꾸는 일은 옛 구조가 이름 없이 해 주던 일(정렬, 여백)을 뽑아 적고 새 구조의 담당을 보고하게 한다 | 옛 구조와 함께 그 일이 빠진다 |
| 같은 변경을 여러 개에 적용하게 할 때는 구조가 다른 표본 2~3개로 먼저 시험하게 하고 메인이 표본 결과를 확인한 뒤 전체에 적용하게 한다 | 표본 하나로 전체에 적용해 놓친다 |
| 결정을 문서에 반영하게 할 때는 그 결정이 걸리는 모듈, API, 서비스를 모두 적고 다른 에이전트가 이미 고친 범위도 적는다 | 한 곳에만 반영된다 |
| 참고 문서를 쓰게 할 때는 확인한 사실과 이미 정한 규칙만 쓰고 정하지 않은 금지와 선택 범위를 새로 만들지 말게 한다 | 정하지 않은 규칙이 문서에 박힌다 |
| 산출물에는 지시와 결정에 없는 요소를 넣지 말게 하고, 필요해 보이면 보고에 제안으로 적게 한다 | 넣은 요소를 찾아 지워야 한다 |
| 끝났거나 멈춘 서브에이전트는 메인이 확실히 멈춘다 | 늦게 깨어나 파일을 덮는다 |
| 구현 계획의 한 항목만 떼어 넘길 때 계획에 모든 항목에 걸리는 공통 제약 절이 있으면 그 절도 읽게 한다 | 공통 규칙이 빠져 잘못 시작한다 |
| 사용자 지시, 검토 지적, 사용자가 고른 선택지는 내 말로 줄이지 않고 원문이나 원문 경로를 붙인다 | 요약을 다른 뜻으로 읽는다 |
| 많은 줄을 규칙대로 바꾸는 일은 꼴마다 바꿀 모양을 표로 빠짐없이 주고, 바꾼 줄을 모두 다시 읽게 한다 | 일괄 변경이 문장을 깨뜨린다 |
| 어미나 글자 수로 판정하는 스크립트로 한꺼번에 바꾸지 말게 한다 | 판정이 어긋난 줄까지 바뀐다 |
| `목표:` 줄, 결정 문서 경로(또는 `결정 문서: 없음(까닭)`), 표보다 높은 정의의 `높임:`(올려 다시 보낼 때는 `올림:`)은 훅 `~/.claude/subagent-system/hooks/brief-check.js`가 검사한다(높임은 `description`에 일 이름이 있을 때만). 훅이 없으면 직접 적는다 | 판단 기준을 짐작하고, 높임은 회고의 근거다 |
| 결정 문서의 칸은 `~/.claude/subagent-system/docs/DOC_WRITING.md` 「결정 문서」를 따른다 | 칸 기준이 두 곳에 있으면 어긋난다 |
| 명세와 구현을 동시에 고치게 할 때는 번역 키나 클래스 이름처럼 양쪽이 정하는 이름은 구현이 정하고 명세는 나중에 맞춘다고 적는다 | 같은 것을 두 이름으로 지어 다시 맞춰야 한다 |

## 이슈 분석과 측정

| 지킬 것 | 이유 |
|:---|:---|
| 지시에 적은 사실(남은 할 일, 기대 결과)은 쓴 시점 기준의 참고라고 적고, 지금 상태와 어긋나면 결정 문서나 원자료로 판정해 보고하게 한다 | 낡은 사실에 맞춰 일한다 |
| 지시에 붙인 기존 스크립트나 시험의 기댓값도 참고라고 적고, 어긋나면 코드 주석과 결정 문서로 판정하며 값에 맞추려 동작을 바꾸지 말게 하며, 고쳐도 되는 기대값은 목록으로 허용한다 | 요구와 어긋나게 동작을 바꾼다 |
| 원인 조사를 맡길 때는 증상이 난 환경(로컬, 스테이징, 운영. 화면은 기기와 OS, 브라우저, 화면 크기, 개발 빌드인지 운영 빌드인지)을 적고, 최종 결과뿐 아니라 중간 도구 호출 기록도 보게 한다 | 환경을 추측해 엉뚱한 곳에서 재현하고, 결과만 보면 헛걸음의 원인을 놓친다 |
| 코드를 고치게 할 때는 고치기 전에 그 자리의 커밋 기록(`git log`, `git blame`)을 보게 한다 | 지난 수정이 막으려던 것을 되살린다 |
| 조사에는 시간 상한을 적고 상한이 되면 찾은 것까지 보고하게 한다 | 끝없이 이어진다 |
| 몇 분 넘는 측정은 다른 작업이 고치는 코드를 따라가지 않는 별도 환경에서 돌리게 한다 | 측정 도중 코드가 바뀌어 결론이 갈린다 |
| 측정을 맡길 때는 잴 범위와 기준 환경(데이터 크기, 동시 요청 수, 측정 횟수, 화면은 기기와 네트워크)을 이름으로 정해 주고, 숫자와 목록에는 계산식과 기준점(무엇에서 무엇까지 잰 값)을 함께 준다 | 기준을 추측해 결과를 비교할 수 없다 |
| 로컬 실행이나 시험이 운영 DB, 메시지 큐, 외부 API에 닿는지 적고, 닿으면 운영 데이터를 바꾸거나 외부로 요청이 나가는 조작을 금지한다 | 운영 데이터가 바뀌고 결제와 알림이 나간다 |
| 가격, 요율, 버전처럼 자주 바뀌는 사실은 공식 출처 URL을 주고 그 페이지에서 읽은 값으로만 판정하게 한다 | 기억으로 단정해 틀린 값을 고친다 |
| 지시문에 적는 이름, 번호, 수치, 코드 사실(동작, 세는 기준)마다 출처(파일과 줄, URL)를 옆에 달고, 달 수 없으면 값을 지우고 「찾아서 확인」으로 쓴다 | 틀린 이름이 사실처럼 남는다 |
| 가리키는 문서, 절 이름, 폴더는 보내기 전에 `rg`나 `ls`로 있는지 확인한다 | 없는 문서를 찾아 헤맨다 |
| 웹 조사는 검색 횟수 한도를 세션이 나눠 쓴다는 점을 고려해 범위를 정하고, 아는 URL은 검색하지 말고 직접 열게 한다 | 한도를 다 써 다른 조사가 막힌다 |
| 지난 세션 기록에서 경위를 찾게 할 때는 서브에이전트 기록이 `~/.claude/projects/<프로젝트>/<세션 id>/subagents/`에 따로 있다고 적는다 | 메인 기록만 뒤지다 늦어진다 |

## 셸과 도구

| 지킬 것 | 이유 |
|:---|:---|
| 여러 에이전트가 로컬 서버나 프로세스를 띄우면 그 사실을 적고, 자기가 띄운 것만 PID로 끄게 한다(이름으로 일괄 종료 금지) | 남의 프로세스가 함께 꺼진다 |
| 임시 파일과 생성 스크립트는 에이전트마다 다른 scratchpad 하위 폴더의 절대경로를 지시에 적고 거기에만 두게 하며 `/tmp`는 쓰지 않게 한다 | 밖에 둔 임시 파일은 지울 때 승인 창이 뜬다 |
| 시험을 돌리게 할 때는 붙여 쓸 시험 명령, 의존성(venv, node_modules) 위치, 린터가 없으면 대신 쓸 확인 방법을 적는다 | 명령을 찾느라 헤매거나 본 폴더에 설치한다 |
| 긴 시험은 `run_in_background`로 돌리고 끝 알림을 기다리게 하며 로그 폴더는 미리 만들게 한다 | 없는 로그 폴더에 써서 실패한다 |
| 시험 종료 코드는 파이프 없이 `cmd > <로그> 2>&1; echo "EXIT=$?" >> <로그>` 꼴로 남겨 `rg '^EXIT=' <로그>`로 찾게 한다 | zsh에서는 파이프 뒤 코드를 못 잡는다 |
| 확인 칸에는 프로젝트 테스트 문서의 중간 확인 명령과 마지막 전체 명령을 붙이고, 전체는 정리 뒤 한 번만 돌리게 한다 | 「전체 통과」만 적은 지시는 전체 시험을 여러 번 돌리게 한다 |
| 사용자 승인이 필요한 외부 동작(메시지 발송, 운영 키 사용, 운영 DB 적용)은 메인이 직접 하고 서브에이전트에는 내용 만들기와 결과 확인만 맡긴다 | 전한 승인을 인정하지 않아 그 단계를 건너뛴다 |
| 서브에이전트에게 보고를 파일로 쓰게 하지 않고 답 본문으로 받으며, 파일이 필요하면 메인이 저장하거나 처음 지시에서 산출물로 정한다 | 저장 요청이 막혀 다시 깨워야 한다 |

## 판단과 리뷰를 맡길 때

| 지킬 것 | 이유 |

| opus-high에 판단이나 리뷰를 맡길 때는 미리 받은 조사 결과와 리뷰할 diff 범위를 넣고 그 밖을 넓게 찾지 말게 하며, 더 볼 것은 보고하게 한다 | 싼 모델이 모은 자료를 Opus가 다시 모은다 |
| 사용자가 검수 기준을 직접 정해 준 경우에는 검수 지시문에 그 기준을 빠짐없이 넣고, 더한 기준은 보고의 하고 알린 것에 적는다. 이 체크리스트가 리뷰 종류마다 정한 기준(머지를 막는 기준)은 묻지 않고 넣는다 | 지적이 늘어 검수가 여러 차례 더 돈다 |
| 코드 리뷰에는 「머지를 막는다」의 기준을 적는다: 되돌릴 수 없는 데이터 변경, 다른 기능 회귀, API 계약 깨짐, 테스트가 무작위로 깨짐 | 심각도를 추측한다 |
| 화면과 앱의 코드 리뷰는 머지를 막는 기준에 접근성 악화, 빌드나 타입 검사 실패, 출시 뒤 고칠 수 없는 설정 변경을 더한다 | 못 고치는 변경이 머지된다 |
| diff에서 뺀 경로가 있으면 그 사실과 그쪽에 기대는 테스트를 돌려 보게 한다 | 깨진 테스트를 늦게 찾는다 |
| 코드 정리 검토에는 「정한 것을 바꾸지 않는다」가 동작 결과만 가리키는지 코드 모양과 이름까지 가리키는지 적는다 | 정해 둔 모양을 바꾸자는 제안이 나온다 |
| 검토자나 조사자에게 동작을 확인하게 할 때는 확인 수단(읽을 소스 파일, 돌려도 되는 시험 명령, scratchpad 사본)을 정해 주고, `claude` 실행(환경 변수를 붙인 변형 실행 포함)과 Claude Code 세션 띄우기, 패키지 내려받기(`npx -y`, `npm i`, `pip install`)를 금지하며, 그 수단으로 확인할 수 없으면 「확인 못 함」으로 보고하게 한다. 사용자 설정을 읽어 실제로 도는 다른 도구도 같다 | 검토자가 파서를 보려고 `claude` 바이너리를 돌려 사용자 설정으로 실제 세션이 열렸고, 그 세션이 패키지를 내려받았다 |
