# 키트 시험 시나리오

이 목록은 키트 자체의 시나리오라 설치되지 않는다. 시험 쓰기 전문은 `TESTING.md`.

목표: 키트가 지켜야 할 동작을 「~하면 ~된다」 문장으로 한 곳에 두어, 시험 없는 시나리오와 시나리오 없는 시험을 맞대 찾게 하는 것

- 쓰는 법은 `TESTING.md` 「무엇을 시험하나」를 따른다. 시험 이름은 그 시험이 지키는 시나리오 문장이나 그 문장의 한 조건을 쓴다.
- 문장은 사용자가 보거나 잃을 수 있는 결과로 쓰고, 경계가 있으면 안쪽과 바깥쪽을 함께 적는다. 근거 절은 줄 끝 괄호에 둔다.
- 시나리오를 더하거나 고치면 기능 문서(APPLY_GUIDE, GUIDE, RETRO)를 먼저 고치고 이 목록을 맞춘다. 문서가 원본이기 때문이다.

## 설치와 업데이트와 제거

- IN-01 개인용으로 처음 설치하면 키트 파일과 기준본이 놓이고 개인용 기본값이 모두 적히며 git 확인 창은 개인용 목록만 더해진다(APPLY_GUIDE 3)
- IN-02 회사용으로 처음 설치하면 회고 방식 ask와 승인 쪽 기본값이 적히고 commit과 push 확인 창까지 더해진다(APPLY_GUIDE 개인용과 회사용)
- IN-03 사용자가 거절한 git 확인 항목은 회사용에서 다시 더해지지 않고 개인용에서는 그 기억이 지워진다(APPLY_GUIDE 개인용과 회사용)
- IN-04 설치하면 사용 기록 훅이 settings.json에 더해지고 회고 쓰기 허용 훅은 개인용에만 더해진다(APPLY_GUIDE 개인용과 회사용)
- IN-05 kit-core 규칙과 retro 스킬은 늘 깔리고 고른 규칙과 스킬만 더 깔리며, 키트에 없는 이름을 고르면 아무것도 쓰지 않고 멈춘다(APPLY_GUIDE Q4, Q5)
- IN-06 커맨드 이름을 바꿔 설치하면 retro 스킬이 그 이름으로 깔린다(APPLY_GUIDE 1)
- IN-07 설정 폴더를 바꿔 두었으면 설치한 문서, 스킬, 훅의 경로가 그 폴더를 가리키고 회고 스크립트도 그 폴더의 설정을 읽는다(APPLY_GUIDE 이 문서를 읽는 법)
- IN-08 이미 설치된 곳에 다시 install하거나 profile이 없거나 틀리면 아무것도 쓰지 않고 멈춘다(APPLY_GUIDE 1)
- IN-09 --dry-run이면 install, update, uninstall 모두 파일을 하나도 바꾸지 않고 같은 결과를 보여 준다(APPLY_GUIDE 이 문서를 읽는 법)
- IN-10 처음 설치가 VERSION을 놓기 전에 끊겼으면 install을 다시 돌려 이어 할 수 있고 update는 거절한다(APPLY_GUIDE 1)

- IN-12 업데이트에서 사용자 고침과 키트 고침이 다른 자리면 둘 다 살고 고치기 전 파일이 옆에 백업된다(APPLY_GUIDE 업데이트)

- CO-07 비용 기록은 같은 agentId면 나중 줄을 쓰고 옛 형식 줄은 건너뛴다(RETRO 비용 기록)

- LG-10 서브에이전트 기록이 없으면 사용량을 -로 두고 한 줄은 적으며, 입력이 깨졌으면 아무것도 적지 않고 세션을 막지 않는다(GUIDE 기록과 회고)
- LG-11 키트 시험은 실제 사용 기록 파일을 바꾸지 않는다(APPLY_GUIDE 확인과 재시작)
- LG-12 사용 기록 메모의 모자람(태그 여럿)과 개선(태그 하나) 표시를 읽고 말 중간의 같은 낱말은 표시로 보지 않는다(GUIDE 기록과 회고)
- LG-13 사용 기록은 일 종류 끝 괄호 부연을 떼어 같은 칸으로 묶고 메모 첫 낱말을 agentId로 읽는다(GUIDE 기록과 회고)
- LG-14 ask-log 훅은 승인 창을 정해진 꼴의 기록 한 줄로 남기고 10초 안의 같은 입력(다른 검사 훅이 적은 것 포함)은 적지 않으며, 깨진 입력과 쓰기 실패에도 출력 없이 0으로 끝난다
- LG-15 ask-log 훅은 회고 쓰기 허용 훅이 settings.json에 걸려 있고 허용하는 요청(회고 잠금 동안 서브에이전트의 방법 파일 쓰기)만 적지 않으며, 허용하지 않는 요청과 훅이 걸리기 전(retroWriteAllow만 켠 상태)의 요청은 적는다

## 쓰기 허용 보호

- WA-01 회고 잠금이 잡힌 동안 서브에이전트가 설정 폴더 아래 방법 파일을 쓰면 확인 창 없이 허용된다(RETRO 권한 확인 창과 연속 실패)
- WA-02 메인 세션 요청, 설정 폴더 밖, 정책 문서와 권한 설정, 빠져나가는 경로, 대소문자를 바꾼 보호 경로, 보호 파일을 가리키는 링크는 확인 창으로 넘긴다(APPLY_GUIDE 개인용과 회사용)
- WA-03 사용자 훅 폴더(~/.claude/hooks/), 키트 훅 폴더, 훅이 돌리는 키트 스크립트 폴더(subagent-system/scripts/), 키트 설정 파일 쓰기는 확인 창으로 넘기고 같은 폴더의 다른 파일은 허용한다(APPLY_GUIDE 개인용과 회사용)
- WA-04 retroWriteAllow가 켜져 있지 않거나 잠금이 없거나 3시간을 넘었으면 확인 창으로 넘긴다(APPLY_GUIDE 개인용과 회사용)
- WA-05 입력이 깨졌으면 아무것도 허용하지 않고 세션을 막지 않는다(RETRO 권한 확인 창과 연속 실패)
- WA-06 config.json의 kitSourcePath가 키트 폴더(subagent-system/VERSION이 있음)를 가리키면 그 아래 열 자리(문서, 정의, 스킬, 규칙, 요율표, CHANGES, VERSION, README) 쓰기도 허용하고 스크립트, 훅, settings-hook.json과 .claude/는 넘기며, 키가 없거나 키트 폴더가 아니면 넘긴다(RETRO 권한 확인 창과 연속 실패)
- WA-07 정의와 스킬의 머리는 BOM이나 앞 공백으로 시작해도 읽어 권한, 훅 키가 있으면 넘기고, 구분선으로 시작하는데 닫는 구분선이 없어 읽지 못하는 파일도 넘기며, 구분선으로 시작하지 않는 문서와 BOM 뒤 열 키만 있는 머리는 허용한다. 머리 줄이 0열 `이름: 값`, 블록 값 내용, 키처럼 보이지 않는 이어지는 줄이 아니면(들여쓴 맵, `?` 키, 따옴표 키, 병합 키, 탭) 넘긴다(RETRO 권한 확인 창과 연속 실패)
