# git 사고 복구

목표: stash나 reset 같은 git 사고가 났을 때 사용자 변경을 잃지 않고 작업 트리를 일하던 상태로 되돌린다.

1. 일하는 모든 에이전트에 파일 쓰기를 멈추라고 알린다. 여럿이 동시에 다시 쓰면 복구가 충돌로 실패한다.
2. `git stash list`, `git reflog`, `git status`로 실제 상태를 직접 본다. stash가 비었는지, 바뀐 파일 수, 일마다 사용자 변경이 살아 있는지 확인한다.
3. `git stash pop`이나 `drop`처럼 작업 트리를 바꾸는 복구는 사용자에게 상황을 보고하고 허락받은 뒤 한 곳에서 한 번에 한다. 방치된 옛 stash도 기본 브랜치에 반영됐는지 확인한 뒤 같은 방식으로 정리한다(지워도 약 90일은 `git fsck`로 복구할 수 있다).
4. 충돌 표시가 남은 파일(`git diff --name-only --diff-filter=U`)이 0건이고 빌드가 통과하면 복구된 것이다.
5. 일을 다시 시킬 때 복구가 끝나 재개한다고 알리고, 손댈 파일은 기억에 기대지 말고 다시 읽으라고 지시한다.

원인은 충돌 표시의 이름으로 가린다. `Updated upstream`과 `Stashed changes`면 stash 충돌이고, `HEAD`나 브랜치 이름이면 merge다. `.git/MERGE_HEAD`가 있는지와 충돌 파일의 수정 시각으로 시점을 좁힌다.
