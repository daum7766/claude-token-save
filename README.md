# Claude Code 설정 묶음

Claude Code를 작은 회사처럼 쓰게 해 주는 묶음입니다. 대화하는 Claude는 관리자, 일을 나눠 받는 서브에이전트는 직원입니다. 일마다 알맞은 모델과 생각 깊이(effort)의 직원에게 맡겨 결과의 질은 지키고 비용과 시간을 줄입니다. 쓰는 동안 기록이 쌓이고, 그 기록으로 맡기는 표를 고쳐 쓸수록 그 사람이 하는 일에 맞게 스스로 나아집니다.

한국어로 Claude Code를 쓰는 사람을 위한 묶음입니다(문서와 규칙이 모두 한국어입니다).

## 얻는 것
- 일마다 맞는 모델로 보내서, 가벼운 일에 비싼 모델을 쓰는 낭비가 줄어듭니다.
- 결과가 모자라면 더 센 모델로 올리고, 질이 떨어지는 방향의 절약은 하지 않습니다.
- 쓸수록 표와 지시문이 내 작업에 맞게 고쳐집니다.
- 입력창 아래에서 모델과 어림 비용을 바로 볼 수 있습니다(agent-meter).

## 만든 사람이 쓴 결과
한 사람의 기록이라 하는 일에 따라 달라집니다.
- 기록으로 잰 값: 한 달(2026-10-11~11-11) 동안 서브에이전트에 맡긴 4,850건은, 같은 토큰을 모두 Opus 5.5로 보냈을 때 들었을 비용보다 26% 덜 들었습니다(어림). 서브에이전트의 모델 고르기만 센 값이고, 낮은 모델이 토큰을 더 쓴 몫과 메인 대화에서 아낀 몫은 들지 않습니다.
- 써 본 느낌: 하루 사용 한도를 90% 가까이 쓰던 날이 30% 안팎에서 끝나는 날이 많아졌습니다. 메인 대화까지 든 느낌이고 기록으로 잰 값은 아닙니다.
- 내 기록으로 보기(라우팅을 깔고 서브에이전트를 쓴 뒤): `node ~/.claude/subagent-system/scripts/work-metrics.js savings`

## 이 키트가 지키는 것
키트를 고칠 때마다 아래 여섯 가지로 판단합니다. 이름 키는 각 묶음의 정의(`bundle.json`의 `serves`)가 어느 조각을 어떤 파일로 맡는지 적을 때 씁니다. `kit-setup.js bundles --json`으로 봅니다.
- `portable`: 내 환경 설정을 다른 컴퓨터에서도, 다른 사람도 가져다 쓴다. 설치 문장 하나로 깔리고 업데이트로 따라간다.
- `no-conflict`: 이미 쓰던 내 설정, 규칙, 스킬, git 훅과 부딪히지 않는다. 겹치면 내 것이 먼저이고 키트는 건너뛰거나 알리기만 한다.
- `kit-only-change`: 업데이트와 다시 맞추기는 키트가 놓은 몫만 바꾼다. 내가 고친 값과 내 파일은 그대로 둔다.
- `self-improve`: 쓰는 동안 쌓인 기록으로 표, 규칙, 지시문이 내 작업에 맞게 스스로 나아진다. 장치(훅, 규칙)를 늘리기보다 더 싼 방법(기계 검사 등)을 먼저 고르고, 늘 읽히는 글자가 걸맞은 효과 없이 늘지 않게 한다.
- `root-fix`: 내가 지적하면 그 자리만 덮지 않고 원인을 찾아 같은 종류에 걸리게 고치며, 되풀이되면 방식을 바꾼다.
- `proactive-fix`: 내가 지적하지 않아도 낭비, 겹침, 어긋난 문서 같은 것을 찾아 고치거나 알린다.
이 공개판에는 `root-fix`를 맡는 묶음(피드백)이 들어 있지 않아, 이 조각은 쉽니다.

## 설치
키트를 받은 뒤 아무 폴더에서 Claude Code를 열고 이 한 문장만 말하면 됩니다.

```
<이 폴더>/subagent-system/APPLY_GUIDE.md 읽고 그대로 적용해줘
```

필요한 것은 node 24 이상과 Claude Code 최신 버전입니다. 키트는 `git clone`으로 받고, 새 버전이 올라오면 `git pull` 뒤 같은 문장을 다시 말하면 업데이트됩니다. 바꾸기 전에 설정을 백업하고, 언제든 멈출 수 있습니다.

## 설치 때 고르는 것
Claude가 하나씩 묻고, 묻는 것마다 바뀔 내용을 먼저 보여 줍니다.
- **개인용과 회사용**: 일하는 방식을 AI가 스스로 바꾸게 할지, 바꾸기 전에 묻게 할지 하나로 고릅니다. 새 외부 모델과 유료 도구는 둘 다 승인을 받습니다.
  - 개인용: 표, 규칙, 스킬, 훅, 정의를 AI가 바로 고치고 만듭니다. 회고도 최종 보고 뒤 저절로 돕니다.
  - 회사용: 고칠 것을 물을 것에 모아 승인받은 뒤 바꿉니다. 회고는 할지 묻습니다.
- **주로 하는 일**: 백엔드, 프론트엔드, 데이터, 인프라, QA, 기획과 문서 가운데 고르면 그에 맞는 출발 표가 깔립니다.
- **묶음**: 이 공개판에는 라우팅과 안전장치 묶음이 있습니다. 하나도 안 골라도 바닥(설치와 갱신 도구, 승인 창 기록, 커밋 검사를 이어 부르는 자리)은 깔립니다.
  - 라우팅(회고 포함): 일마다 맞는 정의에 맡기고 기록으로 표를 고칩니다. 이 체계의 중심입니다.
  - 안전장치: 되살릴 수 없는 재귀 삭제, 커밋하지 않은 변경을 버리는 git 되돌리기, 운영 DB를 바꾸는 Supabase SQL을 실행 전에 막거나 묻습니다. 켜면 지우는 파일을 휴지통으로 옮기게 해 되살릴 수 있습니다.
  - 나중에 `kit-setup.js add --bundles 이름`으로 더하고 `remove --bundles 이름`으로 뺍니다. 뺄 때 고친 설치 값은 보관했다가 다시 더하면 되살립니다.
- **CLAUDE.md 정리**: 이미 쓰던 CLAUDE.md가 길거나 겹치면 줄일 곳을 제안합니다. 고치기 전에 반드시 묻습니다.

사용자를 부르는 승인 창을 설정 폴더의 `permission-asks.jsonl`에 기록하는 훅(ask-log)은 바닥이 늘 설치합니다. 출력 없이 기록만 하고 승인 결정에는 끼어들지 않으며, 라우팅을 고르면 회고가 그 기록을 보고 승인 창을 줄입니다.
라우팅을 고르면 목표와 결정 문서가 없는 서브에이전트 지시문을 보내기 전에 막는 지시문 검사 훅(brief-check)과 agent-meter(화면 아래 비용 표시)도 함께 깔립니다. 자세한 설명은 [agent-meter/README.md](agent-meter/README.md)에 있습니다.

## 평소에 쓰는 법
- 그냥 일을 시키면 됩니다. 메인 Claude가 표를 보고 알맞은 직원에게 맡깁니다.
- 결과가 모자라면 그렇다고 말하세요. 그 말이 표를 올리는 근거가 됩니다.
- 하지 않는 일은 표에서 빼 달라고 하면 됩니다.
- 개인용은 회고가 저절로 돌고, 회사용은 Claude가 회고할지 묻습니다. 지금 하려면 `/retro now`, 상태를 보려면 `/retro`를 칩니다.
- 회고가 사용자에게 물을 것은 설정 폴더의 `docs/PROPOSALS.md`에 쌓이고, Claude가 하나씩 묻습니다.
- 메인 모델은 Opus 5.5 high를 권합니다. 맡기고 확인하는 역할이라 판단이 틀려도 알아챌 신호가 없기 때문입니다.
